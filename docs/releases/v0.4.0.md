# v0.4.0

## Summary

Session discovery now reads what current Codex clients record, lists a large home in seconds
instead of a minute, and keeps a Claude Code session tied to the directory it started in. It
also carries the redaction work that came out of the release review.

## Changes

- **Read the `item_completed` dialogue schema** that current Codex clients write (#7,
  [@akmalayari](https://github.com/akmalayari)). A session recorded by codex-cli 0.150 or later
  imports its user and agent messages again instead of only its tool calls, and the newer
  `McpToolCall`, `CollabAgentToolCall`, `SubAgentActivity` and `Extension` items are understood:
  a server call carries its tool name and arguments, and every result body stays out.
- **Stream each Codex rollout while listing it** (#1). A 2.37 GB home of 2,023 rollouts lists in
  9.4 s instead of 41 s, and a 635 MB rollout that failed with `Invalid string length` lists in
  0.7 s. A damaged or unreadable rollout is now isolated to its own row instead of failing the
  whole home, and a file that a later read refuses is flagged as such rather than opened silently.
- **Keep a session's start directory apart from its active-chain directories** (#5, #6). A resumed
  Claude Code thread is matched by the repository it started in even when the active chain has
  moved into a subdirectory, while a directory that resolves to a different repository still
  excludes the session.
- **Read mixed-era Codex rollouts.** A thread that a newer client resumed keeps the dialogue of
  both eras: the calls it made before the first item turn are still read, and only the coarser
  `response_item` repeats are dropped.
- **Redact every value whole.** A matched value is replaced to its end, so a credential can no
  longer be left partly in place, and the key-name pattern is bounded so a long unbroken line
  cannot stall redaction (200 KB of one word now takes 0.05 s; 50 KB took 11.8 s). Measured over
  190,778 recorded texts (1.28 GB), redaction totals 65 s with a worst single text of 0.29 s.

## Upgrade

- If you maintain a session adapter outside this repository, add `startDirectory` to your
  `SessionDescriptor`: the recorded directory a session started in, or `null` when its home does
  not say. The field is required, and discovery uses it as a last-resort match only when no
  recorded directory matched and none conflicts.
- Restart Pi after updating so the extension and its adapters load from the new package.
- A GitHub release can appear before npm finishes scanning its packages. If a pinned install
  returns `404`, check
  [package availability](../troubleshooting.md#a-new-release-is-not-available-on-npm) before
  retrying.
